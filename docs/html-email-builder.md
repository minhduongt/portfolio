# HTML preview and email builder

The `html-email-builder` component is implemented as a browser utility with a separate lazy-loaded bundle. Its catalog payload is included in [new-tools-catalog.json](./new-tools-catalog.json), defaulting to private for admin review. The existing backend metadata schema already supports this component key. Choose public, limited or private visibility in the admin editor as usual.

The builder starts in a visual editing mode with a component library, selectable email canvas and properties sidebar. Heading, text, image, button, divider, spacer, table and two-column blocks can be added by clicking or dragging. Drop on a gap or the upper/lower half of an existing section to insert or reorder. Selected blocks have move-up/down, duplicate and remove controls; these also support keyboard and touch users. Undo/redo retains up to 50 design changes. The design supports up to 100 blocks. Page scrolling is instant while the visual editor is open so sections remain stable during dragging; the previous scroll behavior is restored on leaving it.

The sidebar edits each section's content, background, padding and alignment, plus text color, size and weight where applicable. Buttons have editable URLs, background and corner radius. Images have alternative text and width controls, plus local PNG/JPEG/GIF/WebP uploads up to 80 KB; uploaded images are embedded in the exported HTML. Table rows and both text columns are editable. Email settings control the document title, outer background and system font.

Welcome, Newsletter and Receipt templates populate both the visual model and HTML draft. Template fields include brand, document title/subject, heading, message, accent color, call-to-action text/URL and footer; Receipt adds order reference, item description and total. Template text is escaped, colors are validated and button URLs require HTTP/HTTPS. Apply template explicitly replaces both drafts; selecting a template alone does not change the design. Visual template replacement can be undone.

Visual mode generates table-based email HTML with inline styles. HTML mode allows arbitrary custom source and updates the live preview. A manually edited HTML draft is kept separately and survives switching back to the visual canvas. Use visual design as HTML explicitly replaces it with generated markup; arbitrary custom HTML is not parsed into visual blocks. Copy and Download HTML export the active editor's source. Desktop and mobile previews use 600px and 375px iframe widths; narrow containers scroll horizontally without overflowing the page. Drafts and history live in browser memory and reset on reload; no backend or sending service was added. The document title is not an actual email subject header. Recipient email clients may render differently from the browser.

Preview isolation uses a sandboxed iframe without scripts or same-origin privileges, dedicated DOMPurify instances and a restrictive CSP. Scripts, forms, frames, refresh metadata and navigation attributes are removed. Inline CSS and embedded data images are supported. External images are blocked by default in both the canvas and iframe. Load external images explicitly permits HTTP/HTTPS images; disabling it restores the restrictive image policy. Scripts, forms and navigation remain blocked in both modes. Blocked CSS resource attempts may appear as failed `csp` requests but receive no network responses. Preview CSS cannot style the portfolio. Export is the generated visual HTML or original custom HTML, not the sanitized preview document. Both modes enforce a 150,000-character source limit.

Validation: `node scripts/check-email-design.mjs` covers templates, eight block types, escaping, URL/style validation and immutable reordering. `node scripts/check-visual-email-builder.mjs` covers the default visual mode, sidebar changes, real native drag/drop, keyboard controls, duplicate/remove, undo/redo, embedded image uploads, external-image opt-in, separate custom HTML drafts, exports, template replacement and responsive layouts. `node scripts/check-email-builder.mjs` preserves the existing HTML template, sanitizer/CSP, isolation, download and exact preview-width checks. Browser checks use the root build preview on port 4177 (override `SITE_URL`) and mocked endpoints; no emails, live tool records or deployments are performed.
